## 1. Motivation and Context

TRACE (Textual Reuse, Alignment, and Collation Engine) is a general-purpose Python library for witness-based textual alignment, collation, and variant analysis. It is designed for textual criticism, fragment comparison, and the construction of digital synopses and critical editions across scripts and traditions.

TRACE is **not domain-specific.** The library itself is built to serve any project that needs philological alignment — regardless of script, tradition, or material (manuscripts, prints, Geniza fragments, papyri, cuneiform, etc.).

The full long-term vision (master alignment graph for many witnesses, Geniza fragment anchor detection across 150 000 fragments, text-reuse detection, family clustering, critical-edition generation) is decomposed into multiple sub-projects. This spec defines **v0.1**, the foundation that all later sub-projects build on.

### Long-term decomposition

| # | Sub-project                                                      | Status            |
| - | ---------------------------------------------------------------- | ----------------- |
| 1 | **Pairwise aligner + Hebrew normalization + tokenization** | This spec — v0.1 |
| 2 | Master alignment graph / incremental multi-witness alignment     | future            |
| 3 | Geniza fragment anchor detection                                 | future            |
| 4 | Text-reuse detection (recurring-phrase alignment)                | future            |
| 5 | Apparatus / critical-edition generation                          | future            |

## 2. Scope of v0.1

### In scope

- **Pairwise aligner**: takes two token sequences, returns a token-level alignment with per-match score and reason.
- **Tokenization**: plaintext input → token list. Architecture-level support for any language; concrete implementation for Hebrew.
- **Normalization**: multi-layer per-token representations (raw, default-normalized, language-specific layers).
- **Scoring**: tiered similarity producing `(score, reason, details)` per token comparison. Reasons are explicit (EXACT, NIQQUD_STRIPPED, PLENE_DEFECTIVE, ABBREVIATION, ORTHOGRAPHIC, etc.).
- **Algorithm**: semi-global Needleman–Wunsch with affine gap penalties, plus a multi-token lookahead for abbreviation expansions (e.g. `ר"י` ↔ `רבי ישמעאל`).
- **Hebrew language pack**: reference implementation. Ships seed lexica (small) for abbreviations and known plene/defective pairs. Lexica are user-extendable.
- **Language-agnostic core**: any language pack can plug in without core changes.
- **I/O**: plaintext input, eScriptorium JSON importer, TEI XML importer, JSON serialization of alignment results.

### Out of scope (deferred to later sub-projects)

- Master alignment graph; incremental multi-witness alignment.
- Anchor-based pre-segmentation; arbitrary-length input handling beyond a few thousand tokens per side.
- Persistence layer / database / Django integration.
- Apparatus generation.
- Text-reuse detection.
- Family / cluster analysis.
- Any language pack other than Hebrew (architecture supports them; no implementations in v0.1).
- Learned scoring weights (full feature vector per match) — recorded as v0.2 candidate.

## 3. Architecture and Module Map

TRACE is a layered pipeline with strict dependency rules. The core is language-agnostic; all linguistic knowledge lives in language packs.

### Package layout

```
src/tracealign/
├── __init__.py            # public API: align(), tokenize(), register_language()
├── model.py               # Pydantic: Token, Match, AlignmentResult, Reason, Lexica
├── tokenize/
│   ├── base.py            # tokenizer protocol, EditorialBracketRules, RawToken
│   └── plaintext.py       # generic NFC + bracket-scan + whitespace-split tokenizer
├── normalize/
│   └── base.py            # normalizer protocol, representation-layer interface
├── score/
│   ├── tiered.py          # generic tiered scoring loop; ScoringTier
│   └── editdist.py        # rapidfuzz wrapper for edit-distance fallback
├── align/
│   └── needleman_wunsch.py # semi-global NW with affine gaps + abbreviation lookahead
├── lang/
│   ├── base.py            # LanguagePack ABC; Lexica
│   ├── registry.py        # register_language, get_language, list_languages
│   └── hebrew/
│       ├── __init__.py    # auto-registers HebrewLanguagePack on import
│       ├── pack.py        # HebrewLanguagePack class
│       ├── tokenize.py    # Hebrew post_tokenize hooks (Maqqef split, etc.)
│       ├── normalize.py   # Niqqud strip, skeleton, abbrev candidates
│       ├── scoring.py     # Hebrew tier predicates
│       └── data/
│           ├── abbreviations.json
│           └── plene_defective.json
├── io/

│   └── result.py          # AlignmentResult ↔ JSON
└── data/                  # cross-language shared data (none in v0.1)
```

### Dependency rules

- `model.py` imports only Pydantic.
- `score/`, `align/`, `tokenize/base.py`, `normalize/base.py` are **language-agnostic**: they import `model` and `lang.base`/`lang.registry`, never any concrete language pack.
- `lang/hebrew/` imports `model`, `tokenize.base`, `normalize.base`, `lang.base` only.
- `io/` may import any module except `align/` (importers should not depend on alignment).
- The public surface is `src/tracealign/__init__.py`; everything else is internal API.

### Data flow

```
plaintext   ──┐
              ├──► tokenize() ──► list[Token]
JSON / TEI  ──┘                       │
                                      ▼
                                 (optional) further processing
                                      │
                                      ▼
                            align(seq_a, seq_b, lang) ──► AlignmentResult ──► JSON
```

The aligner is supposed to be agnostic and fast: it takes two sequences and returns a result. The caller is responsible for chunking large inputs (e.g. by paragraph or by versification unit) before calling `align`.

## 4. Data Model (Pydantic v2)

All types live in `src/tracealign/model.py`.

### `Token`

```python
class Token(BaseModel):
    id: str                                   # stable; auto-generated as f"{seq_label}:{position:06d}" if absent
    position: int                             # 0-based index in source sequence
    raw: str                                  # original incl. niqqud, te'amim, editorial markers
    text: str                                 # default-normalized: NFC, niqqud stripped, brackets removed
    representations: dict[str, str] = {}      # additional named layers populated by language pack (e.g. "skeleton")
    flags: set[str] = set()                   # free-form; conventional names listed below
    source_span: tuple[int, int] | None       # (char_start, char_end) in input plaintext, for UI highlighting
    metadata: dict[str, Any] = {}             # free: witness_id, line_pk, surface_label, bbox, etc.
```

**Conventional flag names** (documented but not enforced by an enum):

| Flag                      | Meaning                                                                   |
| ------------------------- | ------------------------------------------------------------------------- |
| `abbreviation`          | Token is an abbreviation (e.g. carries gershayim)                         |
| `reconstructed`         | Editor-reconstructed (originally wrapped in `[...]`)                    |
| `deletion`              | Scribe-deleted (originally `⟦...⟧`)                                   |
| `insertion`             | Editor-inserted (originally `〈...〉`)                                  |
| `abbreviation_expanded` | Editor expanded abbreviation in source (originally `(...)`)             |
| `lacuna`                | Marked as missing text (originally `…` or `[…]`); `text` is empty |
| `compound_part`         | Part of a maqqef-split compound                                           |
| `numeral`               | Hebrew letter functioning as a number (reserved; not detected in v0.1)    |

Language packs may add additional flags; users may add ad-hoc flags. The set is open by design.

### `Reason`

```python
class Reason(str, Enum):
    EXACT             = "exact"             # raw == raw
    NIQQUD_STRIPPED   = "niqqud_stripped"   # text == text
    PLENE_DEFECTIVE   = "plene_defective"   # skeleton match, ±1 yod/waw difference
    ABBREVIATION      = "abbreviation"      # via lexicon lookup, possibly span match
    ORTHOGRAPHIC      = "orthographic"      # rapidfuzz ratio above threshold
    SCRIPT_VARIANT    = "script_variant"    # reserved; not used in v0.1
    INSERTION         = "insertion"         # token in A, gap in B
    OMISSION          = "omission"          # token in B, gap in A
    NO_MATCH          = "no_match"          # forced match below all tier thresholds
```

### `Match`

```python
class Match(BaseModel):
    token_a: Token | None                # None = gap in A
    token_b: Token | None                # None = gap in B
    score: float                         # ∈ [0.0, 1.0]; 0.0 for gaps and continuations
    reason: Reason
    details: dict[str, Any] | None = None
```

Invariants:

- Exactly one of `token_a` / `token_b` is `None` for `INSERTION` / `OMISSION`.
- Both are set for all other reasons.
- For `ABBREVIATION` continuations (see §6 below), `token_a` and `token_b` are both set; `details["role"] == "continuation"`; `score == 0.0`.

### `AlignmentResult`

```python
class AlignmentResult(BaseModel):
    matches: list[Match]                                          # alignment-order list
    seq_a_meta: dict[str, Any] = Field(default_factory=dict)      # free: witness_id, length, …
    seq_b_meta: dict[str, Any] = Field(default_factory=dict)
    total_score: float                                            # sum(non-continuation match scores) / max(len(seq_a), len(seq_b))
    summary: dict[Reason, int]                                    # counts per reason; ABBREVIATION counts primaries only
    params: dict[str, Any]                                        # gap_open, gap_extend, abbrev_max_span, lang, language_pack_version, trace_version
```

`summary` is computed by the aligner, not by the caller, so it is always consistent with `matches`.

### `Lexica`

```python
@dataclass
class Lexica:
    abbreviations: dict[str, list[str]] = field(default_factory=dict)           # multi-resolution: "ר\"י" → ["רבי ישמעאל", "רבי יהודה", "רבי יוסי"]
    plene_defective_pairs: list[tuple[str, str]] = field(default_factory=list)   # known pairs

    @classmethod
    def load(cls, paths: dict[str, Path]) -> "Lexica": ...
    def merge(self, other: "Lexica") -> "Lexica": ...
```

## 5. Tokenizer Pipeline

### `LanguagePack` interface (`src/tracealign/lang/base.py`)

```python
class LanguagePack(ABC):
    code: str                                       # primary identifier, ISO 639-3 preferred (e.g. "hbo")
    aliases: tuple[str, ...] = ()                   # additional names accepted by the registry
    version: str                                    # e.g. "hbo-0.1.0"; copied into AlignmentResult.params

    word_chars: str | re.Pattern                    # characters that constitute a word
    mid_word_chars: str = ""                        # characters allowed inside a word but not at boundaries
    editorial_rules: EditorialBracketRules = DEFAULT_EDITORIAL_RULES
    lexica: Lexica = field(default_factory=Lexica)

    def post_tokenize(self, raws: list[RawToken]) -> list[RawToken]:
        return raws                                 # default: identity

    @abstractmethod
    def normalize(self, raw: RawToken) -> Token: ...

    @abstractmethod
    def scoring_tiers(self) -> list[ScoringTier]: ...
```

The registry in `lang/registry.py` indexes packs by `code` and every entry of `aliases`. Hebrew auto-registers itself when `tracealign.lang.hebrew` is imported.

### Tokenizer entry point

Public entry point: `tracealign.tokenize(text: str, lang: str | LanguagePack = "hbo", seq_label: str = "seq") → list[Token]`.

### Six-stage pipeline

1. **NFC normalization** of the input string.
2. **Editorial-marker scan**: locate bracket pairs and lacuna markers, record their positions and types, replace contents with placeholders that survive whitespace splitting.
3. **Whitespace + punctuation split** into `RawToken`s. The language pack supplies `word_chars` and `mid_word_chars`. Hebrew lists gershayim `"`, geresh `'`, and maqqef `־` as mid-word characters; this means `ר"י` is *not* split here.
4. **Marker reattach**: bracket spans from stage 2 become flags on the `RawToken`s whose spans they cover.
5. **Language-pack post-pass**: `LanguagePack.post_tokenize(raws)` may merge or split tokens. Hebrew's post-pass splits maqqef compounds (`אֶל־בֵּית` → two `RawToken`s, each with `compound_part`).
6. **Language-pack normalize**: `LanguagePack.normalize(raw) → Token`. Populates `text`, `representations`, additional flags, `metadata` extensions.

### `RawToken` (internal)

```python
@dataclass
class RawToken:
    raw: str
    span: tuple[int, int]
    flags: set[str]
```

Used between stages 3 and 6 only; not part of the public API.

### `EditorialBracketRules`

```python
@dataclass
class EditorialBracketRules:
    pairs: list[tuple[str, str, str]]        # (open, close, flag)
    lacuna_markers: list[str]                 # e.g. ["…", "[…]"]
```

Default rules:

| Marker           | Flag                                   |
| ---------------- | -------------------------------------- |
| `[...]`        | `reconstructed`                      |
| `⟦...⟧`      | `deletion`                           |
| `〈...〉`      | `insertion`                          |
| `(...)`        | `abbreviation_expanded`              |
| `…`, `[…]` | `lacuna` (token with `text == ""`) |

These are conventions, not hard-coded behavior. Language packs can override; users can pass a custom `EditorialBracketRules` to `tokenize`.

### eScriptorium JSON importer

`tracealign.io.escriptorium.load(path_or_dict, lang="hbo") → list[Token]`

Walks the eScriptorium export, extracts the textual content per region/line, and runs the same `tokenize()` pipeline on it. eScriptorium-specific data (line_pk, bounding boxes, witness identifiers) lands in `Token.metadata`. There is no parallel tokenization path.

### TEI XML importer

`tracealign.io.tei.load(path_or_string, lang="hbo", text_xpath: str | None = None) → list[Token]`

If `<w>` tags are present in the body, each `<w>` becomes one token (its text content goes through normalize-only, skipping word splitting). If no `<w>` tags exist, the body text is concatenated and run through the standard plaintext tokenizer. Default XPath: `//tei:body//tei:w | //tei:body//text()`. Complex constructs like `<choice><orig>/<reg>` are **not** auto-resolved in v0.1; users with such markup pass a custom XPath.

## 6. Scoring and Aligner

### Tiered scoring (`src/tracealign/score/tiered.py`)

```python
@dataclass
class TierResult:
    score: float                         # ∈ [0, 1]
    details: dict[str, Any] | None = None

@dataclass
class ScoringTier:
    reason: Reason
    predicate: Callable[[Token, Token, LanguagePack], TierResult | None]

def tiered_score(a: Token, b: Token, pack: LanguagePack) -> Match:
    for tier in pack.scoring_tiers():
        result = tier.predicate(a, b, pack)
        if result is not None:
            return Match(token_a=a, token_b=b, score=result.score,
                         reason=tier.reason, details=result.details)
    return Match(token_a=a, token_b=b, score=0.0, reason=Reason.NO_MATCH)
```

Tiers are returned by `LanguagePack.scoring_tiers()`. The generic scorer iterates them in order and returns the first hit.

### Hebrew tier order

| # | Predicate                                                                                                                                                                                                              | Score            | Reason          |
| - | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- | --------------- |
| 1 | `a.raw == b.raw`                                                                                                                                                                                                     | 1.0              | EXACT           |
| 2 | `a.text == b.text`                                                                                                                                                                                                   | 0.95             | NIQQUD_STRIPPED |
| 3 | `a.representations["skeleton"] == b.representations["skeleton"]` AND `len(a.text) − len(b.text) ∈ {−1, 0, +1}` AND the difference is exactly one yod or waw                                                     | 0.85             | PLENE_DEFECTIVE |
| 4 | One side has flag `abbreviation` AND a candidate in `metadata["abbrev_candidates"]` matches the other side's `text` exactly (1:1 case only — 1:n span matches are handled by the aligner's lookahead, not here) | 0.85             | ABBREVIATION    |
| 5 | `rapidfuzz.ratio(a.text, b.text) ≥ 0.6`                                                                                                                                                                             | `ratio · 0.9` | ORTHOGRAPHIC    |
| 6 | otherwise                                                                                                                                                                                                              | 0.0              | NO_MATCH        |

Tier scores and the orthographic threshold are configurable via `HebrewLanguagePack` constructor arguments.

### Hebrew skeleton

`Token.representations["skeleton"]` is computed in `lang/hebrew/normalize.py` as `text` with all yod and waw characters removed. Combined with the `±1` length and yod/waw-only difference checks in tier 3, this gives a robust plene/defective predicate without false positives like דדה ↔ דדי.

### Hebrew abbreviation candidates

`Token.metadata["abbrev_candidates"]` is a `list[str]` populated when the abbreviation lexicon resolves the token's `text`. Multi-resolution entries (e.g. `ר"י → [רבי ישמעאל, רבי יהודה, רבי יוסי]`) all become candidates; the aligner's lookahead picks the contextually best one.

### Aligner: semi-global Needleman–Wunsch with affine gaps (Gotoh)

Three DP matrices over `m = len(a)` × `n = len(b)`:

- `M[i][j]` — best score ending in match between `a[i−1]` and `b[j−1]`.
- `X[i][j]` — best score with `a[i−1]` consumed, gap in B.
- `Y[i][j]` — best score with `b[j−1]` consumed, gap in A.

Recurrence:

```
M[i][j] = s(a[i−1], b[j−1]) + max( M[i−1][j−1], X[i−1][j−1], Y[i−1][j−1] )
X[i][j] = max( M[i−1][j] + gap_open, X[i−1][j] + gap_extend, Y[i−1][j] + gap_open )
Y[i][j] = max( M[i][j−1] + gap_open, X[i][j−1] + gap_open,   Y[i][j−1] + gap_extend )
```

DP match score:

```
s(a, b) = 2 · tiered_score(a, b, pack).score − 1     # maps [0,1] → [−1, +1]
```

Resulting DP scores per reason: EXACT → +1.0, NIQQUD_STRIPPED → +0.9, PLENE_DEFECTIVE → +0.7, ABBREVIATION → +0.7, ORTHOGRAPHIC@0.6 → +0.08, NO_MATCH → −1.0.

Default gap penalties:

```
gap_open   = −2.0
gap_extend = −0.5
```

These are tuned so two consecutive mismatches (−2.0) are cheaper than a gap-open (−2.0) followed by a single gap-extend (−2.5), encouraging short divergences over insertions, while still allowing block-style insertions to win against many singletons.

### Semi-global modification

- First column initialized so `Y[0][j] = 0` for all `j` — leading gaps in A are free.
- First row initialized so `X[i][0] = 0` for all `i` — leading gaps in B are free.
- Traceback starts from the best value in the last row or last column (rather than fixed `[m][n]`).

This natively supports fragments: a witness whose only the middle is preserved aligns into the middle of a complete witness without rim penalties.

### Abbreviation span lookahead

A fourth DP transition, active only when one side's token carries the `abbreviation` flag:

```
A_a→b[i][j] = max over k in [2, abbrev_max_span] of:
    max(M, X, Y)[i−1][j−k] + abbrev_span_score(a[i−1], b[j−k:j])
A_b→a[i][j] = max over k in [2, abbrev_max_span] of:
    max(M, X, Y)[i−k][j−1] + abbrev_span_score(b[j−1], a[i−k:i])
```

`abbrev_span_score` returns a positive DP score (mapped from the ABBREVIATION tier) if any candidate in the abbreviation token's `metadata["abbrev_candidates"]` whitespace-splits to a token list that matches the span 1:1 by `text` equality. v0.1 requires exact equality per span position — no per-token edit-distance tolerance inside the span. (A future release may relax this; the predicate is local enough to extend without affecting the DP structure.) Returns `−∞` on miss.

When traceback follows an abbreviation-span transition, the output records:

- **One primary `Match`**: `token_a` is the abbreviation, `token_b` is the *first* token of the resolved span. `reason = ABBREVIATION`, `score` is the resolved tier score, `details = {"role": "primary", "expansion": "<resolution string>", "span_size": k, "span_token_ids": [<id of first b>, …, <id of last b>]}`.
- **k − 1 continuation `Match`es**: `token_a` is the same abbreviation token (repeated for renderer convenience), `token_b` is the next token in the span. `reason = ABBREVIATION`, `score = 0.0`, `details = {"role": "continuation", "primary_index": <index of primary in matches list>}`.

This keeps `len(matches)` aligned to the standard NW path length and gives renderers a 1:1 row per consumed token without losing the grouping information.

`summary["abbreviation"]` counts only primary matches.

### Complexity

- Time: `O(m·n + m·n · abbrev_max_span)` ≈ `O(5·m·n)` at the default `abbrev_max_span = 4`.
- Space: three `(m+1) × (n+1)` float matrices plus traceback pointers.

For 2 000 × 2 000 sequences this is ≈ 20 M operations and ≈ 96 MB of matrix memory — sub-second to a few seconds in Python with NumPy. For 5 000 × 5 000 it approaches 600 MB, which is why the caller is expected to chunk inputs (by paragraph, versification unit, or similar) before calling `align`.

### `AlignerConfig`

```python
@dataclass
class AlignerConfig:
    gap_open: float = -2.0
    gap_extend: float = -0.5
    semi_global_a: bool = True
    semi_global_b: bool = True
    abbrev_lookahead: bool = True
    abbrev_max_span: int = 4
```

`score_tier_overrides` is **not** in v0.1; configure tiers via a custom language pack instead.

### `total_score` normalization

```
total_score = sum(m.score for m in matches if m.details is None or m.details.get("role") != "continuation")
            / max(len(seq_a), len(seq_b))
```

Two identical 100-token sequences give `total_score = 1.0`. A sequence with 50 % gaps gives roughly `0.5`. The value is directly displayable as a percentage.

### Implementation notes

- Use NumPy float arrays for `M`, `X`, `Y`; traceback pointers as a small int array.
- The `s(a, b)` evaluation calls Python predicates; cache it with `functools.lru_cache` keyed on `(a.id, b.id)` because the same pair recurs in lookahead loops.
- Order Hebrew tier predicates fastest-first (string equality before regex/lexicon work) so the common case stays cheap.
- No Numba / Cython / multithreading in v0.1. Measure first.

## 8. Acceptance Criteria and Test Plan

### Acceptance criteria for v0.1

**Tokenizer (plaintext):**

- [ ] Gershayim and geresh are mid-word; `ר"י` is one token.
- [ ] Maqqef compounds split; each part flagged `compound_part`.
- [ ] Niqqud and te'amim land in `raw`, are absent from `text`.
- [ ] Editorial bracket pairs become flags, not part of `text`.
- [ ] Lacuna markers produce tokens with `text == ""` and flag `lacuna`.
- [ ] `EditorialBracketRules` is overridable.

**eScriptorium / TEI importers:**

- [ ] eScriptorium export round-trips line_pk, bounding boxes, witness id into `metadata`.
- [ ] TEI with `<w>` tags: each `<w>` becomes one token.
- [ ] TEI without `<w>` tags: body text runs through plaintext tokenizer.

**Hebrew language pack:**

- [ ] Skeleton representation correctly drives plene/defective tier.
- [ ] Multi-resolution abbreviation lexicon populates `abbrev_candidates`.
- [ ] Seed lexica ship (small; ~5–10 entries each) and merge with user-supplied lexica.
- [ ] Pack auto-registers on import.

**Aligner:**

- [ ] Two identical sequences produce `total_score == 1.0` and all-EXACT matches.
- [ ] A fragment that is the middle of a longer witness aligns with no rim penalties.
- [ ] A block insertion of 5 tokens costs less than 5 individual mismatches under default penalties.
- [ ] Each `Reason` value fires in dedicated tests with isolated inputs.
- [ ] `ר"י` ↔ `רבי ישמעאל` produces one primary `ABBREVIATION` match plus one continuation.
- [ ] Default `AlignerConfig` documented; every config field has effect.

**Output:**

- [ ] `AlignmentResult` JSON round-trips losslessly.
- [ ] `summary["abbreviation"]` counts primaries only.
- [ ] `trace_version` and `language_pack_version` are present in every output.

### E2E fixture strategy

Two synthetic Hebrew witnesses are constructed for v0.1, designed to exercise every reason (EXACT, NIQQUD_STRIPPED, PLENE_DEFECTIVE, ABBREVIATION primary + continuation, ORTHOGRAPHIC, INSERTION, OMISSION, NO_MATCH) in a deterministic golden file. ## 9. Decisions Log

Decisions taken during brainstorming, with their rationale, in chronological order:

1. **Scope of v0.1 = pairwise aligner + Hebrew normalization + tokenization.** Rationale: smallest cohesive block that produces a usable engine end-to-end. Master graph, anchor segmentation, text reuse, apparatus generation are deferred to separate sub-projects.
2. **Plaintext is the primary input; eScriptorium JSON and TEI XML are secondary importers.** TRACE owns segmentation and tokenization. Rationale: ensures TRACE is usable standalone without an upstream segmentation system; importers reuse the tokenizer rather than maintaining a parallel path.
3. **Tokenization rules**: gershayim/geresh as mid-word characters (so `ר"י` is one token); maqqef compounds split (`אֶל־בֵּית` → two tokens); editorial brackets become flags, not text content; niqqud/te'amim in `raw` only, stripped from `text`. Rationale: aligns the unit of comparison with the philological intuition while leaving raw evidence accessible.
4. **Match shape = score + reason tag** (Option B), not bare scores or full feature vectors. Rationale: enables reason-driven apparatus generation, gives auditability without overhead, and produces the per-reason statistics needed for thesis publication. Full feature vectors are recorded as v0.2 candidate.
5. **Lexica strategy = ship seed lexica for Hebrew (Option B) on a language-agnostic plug-in core (Option C combined).** Rationale: TRACE works out of the box for Hebrew while remaining reusable for any other language via custom packs.
6. **Aligner does not segment; caller chunks.** Rationale: keeps the aligner one focused responsibility and avoids dragging anchor-detection (a separate sub-project) into v0.1. Speed is a stated benefit.
7. **Algorithm = semi-global Needleman–Wunsch with affine gaps + abbreviation-span lookahead.** Rationale: semi-global supports fragments natively; affine gaps reflect philological reality (block insertions cheaper than scattered noise); lookahead solves the canonical `ר"י` ↔ `רבי ישמעאל` 1:n matching case.
8. **`flags` is `set[str]`, not an enum.** Rationale: open for ad-hoc tagging by language packs and downstream users (e.g. `editor:Frank`); convention is documented but not enforced.
9. **`total_score` is normalized to `[0, 1]`.** Rationale: directly displayable as percentage; matches the user's intuition from the brainstorming discussion.
10. **`summary` is computed by the aligner, not by the caller.** Rationale: ensures it always reflects the actual `matches` list and includes the convention that ABBREVIATION counts primaries only.
11. **Multi-token abbreviation match is reported as one primary plus k − 1 continuation matches** (with the abbreviation token repeated in `token_a`, `score = 0.0`, `details["role"] == "continuation"`). Rationale: keeps `matches` 1:1 to consumed tokens, simplifies renderers, preserves grouping information.
12. **`score_tier_overrides` deferred** to a later release. Rationale: customization is already possible via custom language packs; YAGNI.
13. **DP score mapping `[0, 1] → [−1, +1]`** for the alignment matrix. Rationale: gives the DP a meaningful negative for `NO_MATCH` so gaps and mismatches are weighed correctly. Tier scores remain in `[0, 1]` in the public output.
14. **TEI parser default**: respect `<w>` if present, otherwise plaintext-tokenize the body. No `<choice>` resolution in v0.1. Rationale: handles common TEI shapes without committing to a heavy XML editorial-markup pipeline.
15. **`language_pack_version`** included in every output. Rationale: minimum-viable provenance for reproducibility in publications.
16. **Mini Latin pack demonstrating language agnosticism is not in v0.1.** Rationale: architecture is testable for agnosticism without shipping a second pack; a placeholder demo is YAGNI.
17. **E2E fixture is synthetic Hebrew.** Rationale: TRACE is a general-purpose library; the golden file should not depend on any particular corpus, and synthetic data lets us hit every reason deterministically.

## 11. Development Workflow and Quality Gates

### Branch model

- `main` — current stable release. Updated only via merge from `develop` when a release is cut.
- `develop` — integration branch holding the latest development work.
- `feature/<topic>` — branched off `develop`, merged back into `develop`. The current spec lives on `feature/v0.1-design-spec`.

PRs target `develop`. Direct pushes to `main` are not used.

### Pre-commit quality gates

Every commit on every branch must pass, *before* it is committed:

1. **Linting**: `flake8` against `src/` and `tests/`. Code must be PEP 8 compliant.
2. **Tests**: the full test suite (pytest) must pass.

These are not optional. CI enforces both. Locally, the implementation plan adds a `pre-commit` hook that runs flake8 and a fast-test subset; the full suite is run before pushing.

### Tooling layout

- Linter: `flake8` with project config in `.flake8` or `setup.cfg` (line length and ignore set will be set during the implementation plan; no values are decided here).
- Test runner: `pytest`.
- Type hints: encouraged but not enforced by CI in v0.1.
- No `black` / `isort` mandate yet; if added, the implementation plan documents it.

### Commit-message style

- Plain, factual summaries. No assistant or AI attribution anywhere in commit messages, PR descriptions, or shipping artefacts.
- Conventional-commit prefixes (`feat:`, `fix:`, `docs:`, `test:`, `refactor:`, `chore:`) are encouraged but not required for v0.1.
