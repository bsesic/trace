# TRACE v0.2 — Multi-Witness Master Alignment Graph — Design Spec

**Status:** Approved (brainstorming complete; awaiting implementation plan)
**Date:** 2026-05-21
**Author:** Benjamin Schnabel
**Scope:** Stage 2 of the TRACE long-term vision — multi-witness simultaneous alignment, producing a canonical variant graph plus a derived aligned table.
**Builds on:** [v0.1 design](2026-04-28-trace-v0.1-design.md) (pairwise aligner, Hebrew pack, semi-global Gotoh DP with affine gaps and abbreviation-span lookahead).

---

## 1. Motivation and context

TRACE v0.1 delivers a pairwise philological aligner with a Hebrew language pack. v0.2 lifts the aligner from "two witnesses at a time" to "N witnesses at once", producing a single canonical structure that captures the alignment relationships of an entire witness set.

The immediate driving use case is **Sifra full witness alignment**: nine named witnesses (V66, V31, Parma, Oxford Marshall 45, JTS, London, Weiss, Bomberg print, plus Genizah fragments handled separately under Stage 3) must be aligned simultaneously so editors and apparatus generators can query "what are the readings at position X across all witnesses". Tanhuma and Mishna corpora have the same structural need.

This spec defines **v0.2**, the multi-witness foundation that subsequent stages (Geniza anchor detection, apparatus generation, stemmatic reconstruction, allusion detection, citation graphs, reception history) build on. See [`docs/ROADMAP.md`](../../ROADMAP.md) for the full ten-stage vision.

### Long-term decomposition

v0.2 is Stage 2 of the ten-stage long-term roadmap. It deliberately does not encroach on later stages — see §10 for explicit out-of-scope boundaries.

---

## 2. Scope of v0.2

### In scope

- **Multi-witness aligner**: `align_multi(witnesses, lang, config) -> MultiAlignmentResult` taking `dict[witness_id, list[Token]]` and returning a canonical variant graph plus a derived aligned table.
- **Variant graph data structure**: a DAG where nodes carry a `dict[witness_id, Token]` mapping and edges carry the set of witnesses traversing them.
- **Aligned table view**: rows × positions × tokens (with gaps), re-anchorable to any witness for presentation.
- **Guide tree**: UPGMA-built binary tree from the pairwise distance matrix, returned as a `GuideTree` for downstream use (Stage 7 draft stemma).
- **Pairwise distance matrix**: `1 − total_score` per pair, computed via v0.1 `align()`, kept on the result for Stage 7 reuse.
- **Sequence-vs-graph alignment**: a partial-order alignment (POA) implementation that aligns a single witness against an existing variant graph during progressive merge.
- **JSON persistence**: dump/load of `MultiAlignmentResult` via a dedicated `tracealign.io.multi_result` module (separate from v0.1's `io.result`).
- **Configurability**: `MultiAlignerConfig` exposing the pairwise `AlignerConfig`, `node_match` aggregation (`"max"` default, also `"mean"`, `"min"`), and `guide_tree_method` (`"upgma"` in v0.2).
- **Determinism guarantees**: same input → same output regardless of input dict insertion order, secured by canonical tie-breaking on sorted witness IDs.

### Out of scope (deferred)

- **Transposition detection.** v0.2 aligns linearly. Tokens that appear at different positions in different witnesses are modelled as INSERTION + OMISSION pairs.
- **Apparatus / critical-edition output.** That is Stage 5. v0.2 produces the structures an apparatus generator needs, but not the apparatus itself, and not TEI parallel-segmentation export.
- **Geniza fragment anchor detection.** Stage 3. Fragments are not added to the master graph in v0.2; they are matched against it in Stage 3.
- **Stemmatic reconstruction proper.** Stage 7. The guide tree returned by v0.2 is a UPGMA-derived draft stemma — useful as a starting point but not a phylogenetic-network reconstruction with contamination support.
- **Cross-tradition / cross-script alignment.** Stage 6. v0.2 takes one language pack per call.
- **Allusion / echo detection, cross-genre citation graphs, multi-millennial reception history.** Stages 8–10.
- **Visualisation.** No matplotlib, no Graphviz export, no D3. Only ASCII pretty-printers for the table and guide tree.
- **Performance optimisation pass.** No NumPy vectorisation of the POA DP, no Cython hot path. Sanity targets are informational, not gating.
- **Streaming / incremental "add one witness to existing graph" API.** v0.2 builds the entire graph in a single `align_multi` call. An incremental opt-in API may follow as v0.2.x once the full-build path is stable.

## 3. Architecture

v0.2 adds a new `multi/` subpackage. **No v0.1 code is modified.** Stage 2 is purely additive.

```
src/tracealign/
├── multi/
│   ├── __init__.py
│   ├── distance.py        # pairwise distance matrix via v0.1 align()
│   ├── guide_tree.py      # UPGMA construction
│   ├── graph.py           # VariantGraph, GraphNode, GraphEdge
│   ├── table.py           # AlignedTable, TableColumn, TableCell, re-anchor
│   ├── merge.py           # sequence-vs-graph POA alignment + graph merge
│   └── api.py             # align_multi() + MultiAlignerConfig + MultiAlignmentResult
├── io/
│   └── multi_result.py    # dedicated JSON persistence for MultiAlignmentResult
└── __init__.py            # re-exports: align_multi, MultiAlignerConfig,
                            # MultiAlignmentResult, VariantGraph, GraphNode,
                            # GraphEdge, AlignedTable, TableColumn, TableCell,
                            # GuideTree, GuideTreeNode
```

Dependency flow:

```
align_multi(witnesses, lang, config)
        │
        ▼
distance.pairwise_distances(witnesses)        ← O(N²/2) calls to v0.1 align()
        │
        ▼
guide_tree.build_upgma(distance_matrix)        ← deterministic binary tree
        │
        ▼
merge.progressive_merge(witnesses, tree)       ← post-order, sequence-vs-graph
        │
        ▼
VariantGraph                                   ← canonical internal form
        │
        ├──► AlignedTable                       ← derived view, re-anchorable
        │
        └──► returned via MultiAlignmentResult (graph + table + guide_tree + summary + params)
```

**Properties:**

- **Language-agnostic.** Every module in `multi/` operates on `Token` sequences. Hebrew-specific behaviour stays in `lang/hebrew/`. Adding a new language pack does not require changes to `multi/`.
- **v0.1 reuse.** Pairwise `align()` is the only algorithmic primitive imported from v0.1. `tiered_score` is used inside POA to score new-token-against-graph-node matches.
- **No new external dependencies.** NumPy (for the distance matrix) and the standard library are sufficient. No NetworkX, no SciPy.

## 4. Data model

All serialisable types are Pydantic models with `model_config = ConfigDict(extra="forbid")`. Internal helper types are `@dataclass`.

### 4.1 Variant graph

```python
class GraphNode(BaseModel):
    id: str                                  # stable, e.g. "n:000042"
    tokens: dict[str, Token]                 # witness_id -> Token at this aligned position

class GraphEdge(BaseModel):
    source_id: str
    target_id: str
    witnesses: set[str]                      # which witnesses traverse this edge

class VariantGraph(BaseModel):
    nodes: list[GraphNode]                   # topologically sorted; first = START, last = END (sentinels with empty tokens)
    edges: list[GraphEdge]
    witness_ids: list[str]                   # sorted lexicographically for determinism
```

**Behavioural contract:**

- `START` and `END` are sentinel nodes with empty `tokens` dicts. Every witness path begins at `START` and ends at `END`.
- A node where `len({t.text for t in tokens.values()}) > 1` is a variant locus — multiple witnesses disagree at that aligned position.
- A node with `len(tokens) == 1` is a unique reading of one witness.
- `witness_path(wid)` walks edges with `wid in edge.witnesses` from `START` to `END`, returning the ordered list of `GraphNode`s the witness traverses. Sentinel nodes are excluded.
- `variants()` yields all non-sentinel nodes with `> 1` distinct token texts in `{t.text for t in tokens.values()}`.

### 4.2 Aligned table

```python
class TableCell(BaseModel):
    token: Token | None                      # None = gap
    node_id: str | None                      # back-reference to VariantGraph node (None for gap cells)

class TableColumn(BaseModel):
    cells: dict[str, TableCell]              # witness_id -> cell (every witness has an entry; gap if absent at this position)

class AlignedTable(BaseModel):
    witnesses: list[str]                     # row labels, in display order
    columns: list[TableColumn]
```

**Re-anchoring**: `AlignedTable.re_anchor(base_witness: str) -> AlignedTable` returns a *new* table where:

- `witnesses[0] == base_witness`, others follow in their previous order.
- Columns are ordered so that `base_witness`'s tokens appear in their original sequence; gaps relative to `base_witness` appear as columns where `cells[base_witness].token is None`.
- **The underlying alignment does not change.** Only presentation order does.

### 4.3 Guide tree

```python
class GuideTreeNode(BaseModel):
    is_leaf: bool
    witness_id: str | None                   # set only for leaves
    children: list["GuideTreeNode"]          # binary in v0.2 (UPGMA)
    height: float                            # cumulative distance, monotonically non-decreasing from leaves to root

class GuideTree(BaseModel):
    root: GuideTreeNode
    method: str                              # "upgma" in v0.2
    distance_matrix: list[list[float]]       # N×N, symmetric, zero diagonal; preserved for Stage 7
    witness_ids: list[str]                   # labels for distance_matrix rows/columns; sorted lexicographically
```

The distance matrix is stored on the tree (not merely on the result) so that loading a persisted alignment retains the full information Stage 7 will need.

### 4.4 Top-level result

```python
class MultiAlignmentResult(BaseModel):
    graph: VariantGraph
    table: AlignedTable                      # default-anchored to first witness in guide-tree post-order
    guide_tree: GuideTree
    witness_ids: list[str]                   # canonical order (sorted lexicographically)
    summary: dict[Reason, int]               # aggregated Reason counts across all pairwise alignments used in Phase 1
    params: dict[str, Any]                   # config snapshot + trace_version + language_pack_version
```

`summary` aggregates the per-pair `AlignmentResult.summary` dicts produced during distance matrix computation — useful for "what kinds of variation does this witness set show?" reporting. It is not a per-node accounting; nodes do not carry Reason information in v0.2 (see §5.3).

### 4.5 Config

`MultiAlignerConfig` follows v0.1's `AlignerConfig` style — a `@dataclass`, not a Pydantic model. It is snapshotted into `MultiAlignmentResult.params` (a dict) for persistence, so it does not itself need to be serialisable.

```python
@dataclass
class MultiAlignerConfig:
    pairwise: AlignerConfig = field(default_factory=AlignerConfig)
    node_match: str = "max"                                # "max" (default) | "mean" | "min"
    guide_tree_method: str = "upgma"                       # v0.2: UPGMA only
    gap_penalty_multi: float = -2.0                        # gap penalty for the POA DP in Phase 3
```

`node_match` and `guide_tree_method` are validated at the entry to `align_multi` (raise on unknown values) rather than encoded as `Literal` types — a deliberate choice for runtime ergonomics matching v0.1's convention.

## 5. Algorithm

Three phases, each implemented in its own module.

### 5.1 Phase 1 — Pairwise distance matrix

```python
def pairwise_distances(
    witnesses: dict[str, list[Token]],
    pack: LanguagePack,
    pairwise_cfg: AlignerConfig,
) -> tuple[np.ndarray, list[str]]:
    wids = sorted(witnesses.keys())                        # canonical order for determinism
    n = len(wids)
    D = np.zeros((n, n))
    for i in range(n):
        for j in range(i + 1, n):
            result = align(witnesses[wids[i]], witnesses[wids[j]], pack, pairwise_cfg)
            D[i, j] = D[j, i] = 1.0 - result.total_score
    return D, wids
```

- O(N(N-1)/2) calls to v0.1 `align`. At N=15: 105 calls; each <1 s for 1000–2000-token sequences → seconds-range total.
- The summary entries from every pairwise call are merged into the result's `summary` field.

### 5.2 Phase 2 — UPGMA guide tree

Standard UPGMA — Unweighted Pair Group Method with Arithmetic Mean. Iteratively merge the closest pair of clusters until one cluster remains.

**Tie-breaking** (critical for determinism, see §7.1): when multiple pairs share the smallest distance, pick the pair with the lexicographically smallest `(min(wids), max(wids))` tuple. This makes the algorithm independent of dict insertion order.

The result is a binary tree `GuideTree` with witnesses as leaves and merged clusters as internal nodes. The cumulative `height` of each node records the UPGMA-style "molecular distance" — useful as a Stage 7 stemma starting point.

### 5.3 Phase 3 — Progressive graph merge in tree-order

```python
def progressive_merge(
    witnesses: dict[str, list[Token]],
    tree: GuideTree,
    pack: LanguagePack,
    cfg: MultiAlignerConfig,
) -> VariantGraph:
    order = post_order_witness_ids(tree)                  # canonical merge sequence

    # Initialise with the first witness as a linear chain
    graph = VariantGraph.from_sequence(order[0], witnesses[order[0]])

    # Incrementally add each subsequent witness via POA
    for wid in order[1:]:
        graph = align_sequence_to_graph(witnesses[wid], wid, graph, pack, cfg)

    return graph
```

The post-order traversal of the UPGMA tree visits closely-related witnesses first, so the graph builds early consensus structure before more distant witnesses (e.g. Bomberg print versus manuscripts) are added.

#### Sequence-vs-graph alignment (POA)

A partial-order alignment based on Lee et al. (2002). DP state: `(i, node)` = best score to consume `seq[0..i)` and arrive at `node`. Transitions:

| Transition | Update | Action on traceback |
|---|---|---|
| Match | `dp[i, node] = max over incoming(node) (dp[i-1, n_prev] + node_match_score(seq[i-1], node))` | merge `seq[i-1]` into `node.tokens[wid]` |
| Insertion in seq (gap in graph) | `dp[i, node] = dp[i-1, node] + gap_penalty_multi` | create new node `{wid: seq[i-1]}`, insert between previous node and `node` on the `wid` edge |
| Deletion (skip graph node) | `dp[i, node] = max over incoming(node) (dp[i, n_prev] + gap_penalty_multi)` | the new witness's edge bypasses this node — record `wid` only on edges that skip past it |

Where:

```python
def node_match_score(token: Token, node: GraphNode, pack: LanguagePack, mode: str) -> float:
    scores = [_dp_score(tiered_score(token, t, pack).score) for t in node.tokens.values()]
    return {"max": max, "mean": statistics.mean, "min": min}[mode](scores)
```

`_dp_score` maps the tier score in `[0, 1]` to the DP scale `[-1, +1]` (same convention as v0.1's `_dp_score`).

#### Merge step

After traceback, the new witness is woven into the graph:

- **Matches** extend an existing node: `node.tokens[wid] = seq[i-1]`, and the edge into that node gains `wid` in its `witnesses` set.
- **Insertions** create new nodes between two existing ones, with `tokens = {wid: seq[i-1]}` and edges carrying only `{wid}`.
- **Deletions** leave nodes untouched, but the new witness's outgoing edge skips them — represented by an edge from the last consumed node to the next node along the new witness's path, with `wid` in its `witnesses` set.

After every merge the graph is **re-sorted topologically** so node order remains stable. Node `id`s are assigned as `n:{position:06d}` based on this sort; node ids may therefore change between merges (clients should always work with `id`s from the final result, not from intermediate snapshots).

### 5.4 Why approach 3 (hybrid)?

Alternatives considered and rejected:

- **Pure greedy (no guide tree)** — order-dependent results. `align_multi({V31, P, Bom})` would differ from `align_multi({Bom, V31, P})`. Unacceptable for reproducibility.
- **Pure progressive table (bioinformatics-style)** — needs lossy conversion from aligned table back to variant graph at the end; loses information about complex variant loci. Also doesn't naturally give us the guide tree as a separate first-class output.
- **Hybrid (chosen)** — guide tree provides canonical merge order, POA-based merging stays graph-native end-to-end. Also produces the guide tree as a bonus first-class output (Stage 7 input).

### 5.5 Determinism

`align_multi` is required to be deterministic given the same `dict[witness_id, list[Token]]`, regardless of dict insertion order:

1. **Phase 1** sorts `witness_ids` lexicographically before computing the distance matrix.
2. **Phase 2** uses canonical tie-breaking (§5.2).
3. **Phase 3** uses a canonical post-order traversal (children visited in `(left, right)` order where left has the smaller `min(witness_ids_under_subtree)`).
4. **Node id assignment** follows the topological order of the final graph.

Property test (§7.1) enforces this.

## 7. Test strategy

### 7.1 Permutation-invariance property

The single most important new test in v0.2:

```python
def test_align_multi_is_permutation_invariant():
    seqs = {"V31": tokens_v31, "P": tokens_p, "Bom": tokens_bom}
    result_a = tracealign.align_multi(seqs, lang="hbo")

    seqs_reordered = {"Bom": tokens_bom, "V31": tokens_v31, "P": tokens_p}
    result_b = tracealign.align_multi(seqs_reordered, lang="hbo")

    for w in seqs:
        path_a = [n.tokens[w] for n in result_a.graph.witness_path(w)]
        path_b = [n.tokens[w] for n in result_b.graph.witness_path(w)]
        assert path_a == path_b

    variants_a = {frozenset((wid, t.text) for wid, t in n.tokens.items())
                  for n in result_a.graph.variants()}
    variants_b = {frozenset((wid, t.text) for wid, t in n.tokens.items())
                  for n in result_b.graph.variants()}
    assert variants_a == variants_b
```

Justifies the choice of approach 3 over pure greedy.

### 7.2 Lossless reconstruction

For every witness `wid`, `[n.tokens[wid] for n in result.graph.witness_path(wid)]` must equal the original input token list.

### 7.3 Unit tests per module

| Module | Tests |
|---|---|
| `distance.py` | Symmetry; diagonal zero; identical sequences → distance 0; disjoint sequences → distance close to 1; determinism |
| `guide_tree.py` | UPGMA correctness on a small 3-witness case with hand-verified result; all leaves present; non-decreasing heights from leaves to root; tie-breaking on sorted IDs |
| `graph.py` | `VariantGraph.from_sequence` produces a linear chain; `witness_path` reconstructs input; Pydantic round-trip preserves node IDs and edge witness sets; topological sort is stable |
| `table.py` | `re_anchor` reorders rows and columns without changing alignment relationships; cells match `witness_path` for each witness |
| `merge.py` (POA) | Empty graph + sequence → linear chain; identical sequence to existing single-witness graph → all tokens merged into existing nodes; one insertion in new sequence → exactly one new node at the right position; one deletion → existing node keeps its tokens, edges skip via the new witness |

### 7.4 Integration tests

- Single witness: linear graph, one-row table, distance matrix is `[[0.0]]`.
- Two identical witnesses: linear graph with every node holding both witnesses; distance 0; guide tree is a single cluster.
- Two disjoint witnesses: graph with parallel paths between START and END.
- Three witnesses with mixed agreement: variant loci at the disagreement positions; aggregate `summary` reports the expected Reason counts.

### 7.5 End-to-end golden test

Four synthetic Hebrew witnesses chosen to exercise the multi-witness feature spectrum:

```
W1: שלום עולם רַבִּי דויד אמר מחר
W2: שלום עולם רבי דוד אמר מחר
W3: שלום עולם ר"י אמר מחר
W4: שלום עולם רבי דוד אמר טוב מחר
```

Expected:

- Distance matrix relations: `D(W1, W2) < D(W1, W3)`; `D(W1, W4) > 0` because of the inserted `טוב`.
- Guide tree: W1 and W2 cluster first (highest similarity after niqqud stripping); W4 attaches latest because of the insertion.
- Variant loci: the "רבי"-position carries three distinct readings (`רַבִּי` with niqqud, `רבי` plain, `ר"י` abbreviation); the "טוב"-position carries only W4.
- `result.table.re_anchor("W4")` reveals `טוב` as a present column with gaps for W1/W2/W3.

## 9. Risks and mitigations

| Risk | Mitigation |
|---|---|
| **POA DP correctness** is the most complex new algorithm. Off-by-one errors in indexing or backpointers can silently produce wrong alignments. | Hand-verified small unit tests for every transition; lossless reconstruction property as a strong invariant. |
| **Memory footprint** at Sifra scale (~15 witnesses, ~3000 tokens each) — the DP matrix at the last merge step has `O(|seq| × |graph_nodes|)` cells. | Sanity-target check in §7.6; sequence-vs-graph is computed against the *current* graph (which grows but stays smaller than the cumulative token count due to merging at consensus nodes). |
| **Tie-breaking ambiguity** in UPGMA — multiple pairs with the same smallest distance can produce different trees if tie-breaking is order-sensitive. | Canonical tie-break on `(min(wid), max(wid))` lexicographic order. Permutation property guards. |
| **Node ID instability** across merges — clients holding onto node IDs from intermediate snapshots could be confused. | Final `MultiAlignmentResult` carries definitive IDs only. The API does not expose intermediate snapshots. |
| **Abbreviation handling weaker in multi-phase** — abbreviation-span lookahead is used in Phase 1 (pairwise) and inside `tiered_score`, but the POA DP itself treats abbreviations as ordinary tokens. | Documented as known limitation in §10; Phase 1 distances still pick up abbreviation relationships; if a witness pair contains many abbreviations, their distance reflects that. |

## 11. Decisions log

1. **Output model is both graph and table.** Graph is canonical, table is a derived view; re-anchoring is presentation-only. Decided 2026-05-20.
2. **Scope is the core only.** No apparatus, no CollateX-compat I/O; preserve the ship-per-stage discipline. Decided 2026-05-20.
3. **Scale target is Sifra-first.** v0.2 builds for ~15 witnesses; NT-scale (hundreds) is deferred. Decided 2026-05-20.
4. **Algorithm is hybrid (guide tree + greedy graph merge).** Order-stable from the guide tree; graph-native from POA-based merging. Decided 2026-05-20.
5. **`node_match` aggregation defaults to `"max"`, configurable.** Permissive cluster growth; CollateX-aligned behaviour. Decided 2026-05-20.
6. **Input is `dict[witness_id, list[Token]]`.** Explicit witness IDs throughout, no positional indexing. Decided 2026-05-20.
7. **`align_multi` lives at the top level** like v0.1's `align`. Re-exports cover the multi-witness types. Decided 2026-05-20.
8. **JSON persistence lives in `tracealign.io.multi_result`**, a dedicated module, not an extension of `io.result`. Decided 2026-05-20.
9. **Permutation invariance is a hard correctness property** with a dedicated property test. Justifies the guide tree's existence. Decided 2026-05-20.
10. **Lossless reconstruction is a hard correctness property** — every input witness must be exactly reconstructible from its path through the result graph. Decided 2026-05-20.
11. **Abbreviation-span lookahead is used in Phase 1 only**, not in the POA DP, to keep complexity manageable. Decided 2026-05-20.
12. **No transposition detection.** Linear alignment only. Decided 2026-05-20.
13. **Guide tree is built via UPGMA** with canonical tie-breaking on sorted witness IDs. Neighbor-joining is deferred. Decided 2026-05-20.
14. **The guide tree's distance matrix is preserved on the result** so Stage 7 can reuse it without recomputation. Decided 2026-05-20.
